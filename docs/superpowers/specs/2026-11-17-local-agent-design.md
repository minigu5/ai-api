# local-agent — 로컬 모델을 하위 작업자로 쓰는 명령어

2026-11-17 · 승인: 사용자 (팀장/직원 설명에 "1 예")

## 왜

Claude Code·Codex(메인테이너, 고성능 Claude)가 사용자 요구를 받아 지시문으로 정리하고,
실제 파일 읽기·수정은 학교 Mac mini 클러스터의 로컬 모델(작업자)이 한다.
목적은 **Claude API 토큰 절약**. 장기적으로 학생 PC에도 같은 방식 제공(이번 범위 아님).

## 목표 / 비목표 / 실패 조건

- 목표: 메인테이너가 명령어 하나로 작업자에게 코드 수정을 맡기고, 결과를 검증하고,
  같은 세션에 다시 지시하는 반복을 할 수 있다. Claude Code와 Codex 양쪽에서 쓸 수 있다.
- 비목표: 여러 학생 동시 사용, 여러 Mac에 요청 분산, 새 하네스 개발, 클러스터 관리(omm이 함).
- 실패 조건: 작업 과정 전체가 메인테이너 컨텍스트로 들어와 토큰이 오히려 늘어나는 것.
  작업자가 "다 됐다"고 한 것을 검증 없이 받아들이는 흐름.

## 근거 (2026-11-17 시험, 과제 1개·조합당 1회)

| 조합 | 시간 | 숨김 채점 |
|---|---|---|
| pi + Qwen3.6-35B-A3B-8bit | 158 s | 5/5 |
| claude -p + 35B-A3B | 334 s | 4/5 |
| pi + Qwen3.8-27B-8bit | 1191 s | 5/5 |
| claude -p + 27B | 1207 s | 4/5 |

claude -p 작업자는 두 번 다 같은 요구를 놓치고 "모든 테스트 통과"라고 보고 → 검증 필수.
exo는 접두 캐시를 재사용함(같은 앞부분 재전송 1~1.3 s).

## 방식 (검토한 것)

1. **명령어 하나 + 작업자 교체 가능 (채택)** — `local-agent`가 pi(기본) 또는 claude -p를 실행.
   양쪽 메인테이너가 셸로 부를 수 있고, 모델 비교를 같은 틀에서 계속할 수 있음.
2. MCP 서버로 감싸기 — Claude Code에 도구로 보이지만 Codex·셸 재사용성이 떨어지고 만들 게 많음. 나중에 1 위에 얹을 수 있음.
3. Claude Code 서브에이전트 — 서브에이전트는 Anthropic 모델만 지정 가능해서 불가.

## 설계 (결정된 것)

- 명령: `local-agent "지시문" [--dir 저장소] [--model ID] [--harness pi|claude] [--continue 세션ID]`
- 기본값: harness pi, 모델 `mlx-community/Qwen3.6-35B-A3B-8bit`(node4에 로드됨),
  게이트웨이 `https://10.80.118.138:52440`, 토큰 `~/.config/ai_api/token`, CA `~/.config/ai_api/ca.pem`,
  pi 설정 `PI_CODING_AGENT_DIR=~/.config/ai_api/pi`(사용자 ~/.pi는 건드리지 않음).
- 출력(표준출력, 짧게): 작업자 최종 요약, `git diff --stat`, 새 파일 목록, 세션 ID, 걸린 시간, 로그 경로.
  전체 과정 로그는 파일로만 저장.
- `--dir`이 git 저장소가 아니면 거부. 작업자는 커밋하지 않음(커밋은 메인테이너 몫).
- `--continue`는 같은 작업자 세션을 이어서 다시 지시(pi 세션 / claude --resume).
- 메인테이너 사용 지침: Claude Code 스킬 + Codex용 AGENTS.md 조각.
  흐름 = 받아들일 조건을 적은 지시문 → 실행 → diff 일부와 테스트를 직접 확인 → 부족하면 `--continue` → 통과 시 커밋.
- 게이트웨이 접속 실패·모델 미로드 시 한 줄 원인과 확인 명령을 출력하고 0이 아닌 종료 코드.

## 빌더에게 맡기는 것
