# local-agent로 작업 맡기기

너는 메인테이너다. 직접 파일을 많이 읽고 고치는 대신, 학교 클러스터의 로컬 모델(작업자)에게 맡기고 결과를 검증한다.

## 맡길 일 / 맡기지 말 일

- 맡길 일: 여러 파일을 읽고 고치는 구현, 테스트 작성, 리팩터링, 반복 수정.
- 맡기지 말 일: 비밀값(토큰·비밀번호) 다루기, 커밋·푸시, 설계 결정, 몇 줄짜리 수정(직접 하는 게 싸다).

## 1. 지시문 쓰기

작업자는 이 대화를 모른다. 지시문 하나로 일할 수 있게 쓴다.

- 목표: 무엇을 왜 바꾸는지.
- 받아들일 조건: 끝났다고 판단할 기준과 실행할 테스트 명령(예: `python -m pytest -q`).
- 범위: 건드릴 파일, 건드리지 말 파일.
- 마지막 줄: "끝나면 바꾼 내용을 짧게 요약해."

작업자(작은 모델)가 자주 하는 실수를 지시문에서 미리 막는다.

- **작게 쪼갠다.** 한 번에 파일 1~3개, 5~10분 안에 끝날 단위로 맡긴다(예: 함수+테스트 / API / 화면 / 문서). 큰 일을 통째로 맡기면 헤매다 시간 초과가 난다.
- 기존 파일을 통째로 다시 쓰지 말고 필요한 부분만 고치게 한다. 테스트 파일은 끝에 덧붙이게 한다(전에 기존 테스트 39개를 지운 적이 있다).
- 쓸 수 있는 도구·환경을 알려 준다(예: pytest-asyncio 없음 → 동기 테스트만, 새 패키지 설치 금지).
- 확인 명령을 지시문에 정확히 적고 "실제로 실행해서 결과를 보고해"라고 쓴다. 작업자는 실행 없이 "통과할 것"이라고 보고하곤 한다.
- 지시문에 코드를 넣을 때는 따옴표·백슬래시가 셸을 거치며 깨지지 않게 파일에 적어 두고 그 경로를 알려 준다.

## 2. 실행

작업은 몇 분씩 걸린다. Claude Code에서는 Bash를 **백그라운드(`run_in_background: true`)로** 실행하고 끝났다는 알림을 기다린다. 앞에서 실행하면 셸 도구 시간 제한(기본 2분, 최대 10분)에 걸려 중간에 끊긴다. 끊기면 local-agent가 작업자를 멈추고 `status: interrupted`로 보고한다. Codex처럼 백그라운드가 없으면 `--timeout`을 셸 제한보다 짧게 준다.

```bash
local-agent --dir <저장소> "<지시문>"
```

보고는 `status`, `session`, `time`, `summary`, `changes`(git diff --stat), `new files`, `log` 순서로 나온다.

## 3. 검증 (생략 금지)

작업자의 요약은 믿지 않는다. 시험에서 작업자가 조건을 놓치고도 "모든 테스트 통과"라고 보고한 적이 있다.

1. `changes`와 `new files`로 범위가 맞는지 본다.
2. 필요한 파일만 `git diff -- <파일>`로 읽는다. 전체 diff를 통째로 읽지 않는다.
3. 테스트를 직접 실행한다. 필요하면 받아들일 조건을 확인하는 테스트를 직접 하나 더 돌린다.
4. **화면·서버 작업은 실제로 띄워서 확인한다.** 진입점(서버 시작, 페이지 열기)을 직접 실행하고, 화면이면 브라우저로 본다. 시험에서 작업자가 "통과"라고 했지만 시작할 때 NameError로 화면이 안 뜬 적이 있다.
5. 새 파일이나 지워진 줄이 의도 밖이면(`changes`에서 삭제 줄이 많을 때) 먼저 되돌릴지 판단한다.

## 4. 다시 지시

부족하면 같은 세션에 구체적으로 지시한다.

```bash
local-agent --dir <저장소> --continue <session> "<무엇이 틀렸고 어떻게 고칠지>"
```

`--dir`은 처음 실행 때와 같은 폴더여야 한다(세션은 폴더에 묶인다). 다르면 종료 코드 2로 거부된다.

같은 일로 3번 넘게 실패하면 직접 고치거나 사용자에게 보고한다. `failed (model error)`는 모델이 깨진 응답(예: 형식이 틀린 tool call)을 낸 것이니, 같은 세션에 `--continue`로 한 번 더 시키거나 더 작게 쪼갠다.

## 5. 마무리

검증을 통과하면 메인테이너가 커밋한다(작업자는 커밋하지 않는다).

## 종료 코드

- 0: 작업자 정상 종료(그래도 검증은 한다)
- 2: 시작 전 점검 실패 — 출력된 한 줄 원인과 확인 명령을 사용자에게 전달
- 3: 작업자 비정상 종료, 4: 시간 초과, 5: 중간에 끊김 — 보고된 변경(반쯤 된 상태일 수 있음)을 확인하고 다시 지시하거나 직접 처리

## 옵션

- `--model <id>`: 다른 클러스터 모델(그 모델이 로드돼 있어야 함)
- `--harness claude`: pi 대신 Claude Code를 작업자로
- `--timeout <초>`: 기본 1800
